2 · Curar stage curar

Vuelve a leer todo el crudo, lo convierte en tablas y se queda con una sola captura (la más completa) de cada sondeo. Es determinista: el mismo crudo da siempre el mismo resultado.

entra
data/raw/source=*/: todos los payloads crudos de las cinco fuentes.
hace
ingest/reprocesar.main
 └─ reprocesar(root, source)          una fuente entera, payload a payload
     ├─ sources.read_raw              lee el NDJSON gzip
     ├─ sources.parse                 parse_emt / parse_trafico_* / parse_valenbisi / parse_renfe
     │   └─ resolver_convencion       (EMT) ¿este sondeo viene en UTC o en hora local?
     └─ clave_sondeo                  agrupa capturas del mismo sondeo; gana la más completa
sale
data/curated/source=*/ (Parquet por fuente y día) · metrics/curar.json (payloads, errores, duplicados)
trampas
001
El gid identifica el refresco de la tabla, no el bus: solo sirve para nombrar el sondeo. test_emt_snapshot_id_es_el_gid_minimo_del_bloque
002
La EMT alterna UTC y hora local de un sondeo al siguiente; un desfase fijo deja el 20 % de las filas 2 h movidas. test_serie_con_convenciones_alternas_ninguna_fila_desplazada
003
La raíz de Renfe es un objeto; sin filtrar nucleo == "40" entra la flota nacional. test_renfe_filtra_solo_nucleo_40
019
Renfe omite la clave que no tiene valor; con 1-3 trenes la columna no existe. test_renfe_tolera_trenes_de_valencia_sin_una_clave
005
34 filas de la capa 192 llegan sin tramo, sin geometría y sin estado: no son tramos. test_filas_hueco_de_trafico_se_descartan
011
La primera captura de un sondeo puede ser el bloque a medio reinsertar; quedarse la primera tira 109.063 posiciones. test_reprocesar_completa_el_sondeo_que_llego_a_medias

Un {"error": …} no es un sondeo: contar líneas dio por completo un día con 3 h 45 min sin posiciones. Se mide en analysis/medir_completitud.instantes y decide features.excluir_dias. test_un_payload_de_error_no_cuenta_como_sondeo

3 · Prepare stage prepare

Pasa de posiciones sueltas a «este bus llegó a esta parada con X segundos de retraso». Es la capa más delicada: un error aquí contamina todas las etiquetas sin dar la cara.

entra
data/curated/ (posiciones EMT) + data/raw/gtfs/ (horario y trazados, todas las versiones).
hace
prepare.procesar_dia(dia)
 ├─ cargar_dia                       lee un día de data/curated
 └─ etiquetar_dia
     ├─ tracking.rastrear            ¿qué posiciones son del mismo bus?
     │   └─ _coser_alternancias      cose el sentido invertido a mitad de ruta
     └─ etiquetado.etiquetar
         ├─ gtfs.elegir_horario      qué versión del GTFS rige ese día
         ├─ mapmatching.emparejar    sitúa cada posición sobre su trazado
         ├─ _segmentar               corta el recorrido en viajes
         └─ _asignar_tramo           casa cada viaje con el programado
             └─ cruces               instante de paso por cada parada → retraso
sale
data/interim/emt_tracked (posiciones con vehicle_id) · data/interim/viajes · data/interim/pasos (con retraso_s) · metrics/prepare.json
trampas
004
Ordenar con quicksort mezcla filas del mismo sondeo: dio un 11 % de precisión siendo 99 %. test_rastrear_no_reordena_filas_dentro_del_sondeo
007
Dos buses de la misma línea en fila india empatan y se intercambian la identidad. test_convoy_en_fila_india_no_intercambia_identidad
008
La puerta de velocidad sobre la posición predicha dejaba colar buses a 110 km/h. test_la_puerta_fisica_se_respeta_tras_sondeos_perdidos
009
Tras un sondeo perdido, el predictor extrapola el doble. test_un_sondeo_que_falta_no_rompe_la_identidad
013
Una posición atrasada parece ir a 88 km/h y parte la línea 24 en carretera. test_un_bus_cuyas_posiciones_llegan_con_retraso_no_se_parte
014
La EMT publica a ratos el sentido contrario de un bus que sigue su marcha. test_la_alternancia_del_trayecto_no_parte_la_trayectoria
012
rastrear reordena: una columna pegada por posición a su salida se cruza entre filas. test_el_orden_de_las_filas_de_entrada_no_cambia_la_etiqueta
006
Filtrar por caja geográfica tira las líneas 24 y 25 bajando a El Perellonet. test_lejos_del_centro_pero_sobre_la_ruta_no_se_descarta
010
shape_dist_traveled es el horario reescalado, no distancia: con él el retraso sale cero. test_la_abscisa_es_geometria_y_no_shape_dist_traveled
015
El horario no cuenta desde la medianoche: el día del cambio de hora casaba con el viaje de una hora después. test_el_dia_del_cambio_de_hora_el_horario_va_con_el_reloj_de_la_calle
reglas
toda columna se une por índice o clave, nunca por posición
el GTFS se elige por fecha de servicio ADR-014
map-matching por distancia al trazado, nunca por caja
tracking no importa el GTFS; rastrea en una pasada ADR-012, ADR-013
flota sintética con retraso conocido, ±5 s en cada parada tests/test_etiquetado.py
compruébalo

5 · Features stage features, y features_h por horizonte

Construye la tabla del modelo: una fila por paso, con el retraso h paradas más allá como objetivo y solo variables que ya se sabían en t_disp. Y la parte en entrenamiento y prueba por fechas.

entra

hace

 ├─ con_disponibilidad                une t_disp a cada paso por clave
 ├─ construir                         objetivo a h paradas + variables
 │   ├─ _ventana_linea / _tramo_flota  lo que ya se sabía de la línea y del tramo
 │   ├─ _sesgo_tramo                  cuánto se equivoca el horario en ese tramo

 ├─ partir                            split TEMPORAL por día de servicio
 ├─ soporte_por_linea                 qué líneas tienen cifra propia
 └─ baselines                         los listones sin modelo
sale
data/processed/train.parquet · data/processed/test.parquet (y data/processed/h<h>/) · metrics/features.json con los baselines
trampas
Ninguna propia. Aquí se usa el arreglo de la 017: todo se mide contra t_disp.
reglas

7 · Servicio fuera de DVC · services, api y ui

Carga los modelos una vez al arrancar y los expone por HTTP. La entrada es el vector de variables ya calculado: el servido en tiempo real está pendiente (ADR-016).

entra
models/ al arrancar · una petición HTTP con el vector de variables.
hace
api/main.lifespan
 └─ Servicio.desde_disco              carga los modelos UNA vez, no por petición
api/routers/prediccion
 ├─ GET  /modelos                     Servicio.modelos
 ├─ POST /prediccion/retraso          Servicio.retraso      → predict.predecir
 └─ POST /prediccion/mas-de-5min      Servicio.mas_de_5min  → predict.probabilidad
ui/app                                habla con la API por HTTP (requests)
sale
JSON con los segundos de retraso, o la probabilidad de llegar más de 5 min tarde y la decisión. Swagger en /docs.
trampas
Ninguna registrada.
reglas
ui no importa services ni carga el modelo: solo HTTP
api valida (Pydantic) y delega; sin lógica de negocio test_un_cuerpo_mal_formado_no_llega_al_servicio
la predicción es la de predict sobre la misma fila test_la_prediccion_es_la_de_predict_sobre_la_misma_fila
el vector trae exactamente las variables del modelo test_el_vector_trae_exactamente_las_variables
una línea no vista predice como dato faltante test_un_vector_con_nulos_y_una_linea_no_vista_predice
un modelo que falta no tumba el arranque test_un_modelo_que_falta_no_tumba_el_arranque
compruébalo
uv run pytest tests/test_api.py tests/test_servicio.py

Guardias que cubren todo el flujo

mutantes
auditoria/mutar.py rompe a propósito cada invariante y exige que algún test caiga (ADR-011). Un test en verde no demuestra que guarde nada; un mutante en rojo, sí. uv run python auditoria/mutar.py (~40 min).
DVC
Cada stage declara sus deps, params y outs en dvc.yaml: si cambia un fichero o un parámetro, uv run dvc repro rehace esa etapa y las de debajo, y nada más.
fronteras
La dirección de dependencias de CLAUDE.md: ingest no mira aguas abajo, ui solo habla HTTP, services es lo único que carga modelos. Se audita con /check-fronteras.
trampas
uv run pytest .claude/tests comprueba que cada trampa cerrada cita un test que existe.
